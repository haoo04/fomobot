# M1 市场注册与行情采集

在 M0 基础上接入 Bitget 和 Hyperliquid 公共行情。验收规模为每家同时启用 10 个市场，每个市场默认监控 `3m`、`5m`、`1h`。

## 实现顺序

1. 新增市场目录、监控配置、已收盘 K 线、OI 快照和最新报价的 SQLite 迁移。按交易所、市场类型、产品类别、DEX 和原生符号保持市场 ID 稳定。启动、每 6 小时和手动同步。继承失败分区的上次成功结果并标记陈旧，停止订阅已确认下线的市场，保留历史。
2. 接入 Bitget V3 公共 REST 和 WS，优先批量读取 V3 OI，对明确不支持的产品使用独立计量来源的 Classic V2。Hyperliquid 发现现货、原生永续和 HIP-3，接入 K 线、买卖一价和资产上下文。永续每 60 秒采样 OI，现货显示 N/A。
3. 用 WS 预览盘中更新，收盘后默认等待 5 秒再用 REST 确认。每周期尝试回填 500 根，少于 300 根有效历史显示预热中。校验 UTC 和精确十进制，幂等入库。实时收盘首次入库才发布事件。连接与请求限流按来源隔离，断线和重启从最后确认点重叠回补。
4. 按 `isReality` 识别 rToken。只有三根连续且完整的 REST 收盘 1m 才能合成 3m。缺线、缺量或接口不可用时显示相应原因。Bitget 日线经 UTC 边界实测后开放。
5. 提供管理员市场目录、同步、监控配置、批量启停和诊断 API。控制台展示市场能力、可选周期、最新 OHLCV、点差、OI 时间、连接和缺口。

## 验收

- 验证空库及 M0 旧库迁移、稳定 ID、配置唯一性、批量写入原子性和鉴权。
- 用固定 REST/WS 样本同时监控 60 条默认周期流，验证 429、未收盘、重复、乱序、缺量、断线、重启及单源故障隔离。
- 在可联网的本机联调双源、Reality 可用性、三周期展示和控制台启停。
- 由用户手动运行 `npm.cmd install`，验收运行测试、类型检查、lint、格式检查和构建，核对后在本地 Git 提交。

## 验收记录

- 空库和已有管理员的 M0 库均完成迁移。固定样本覆盖两家各 10 个市场的 60 条周期流、断线隔离、回补和重启去重，并验证目录失效、收盘校验、OI 降级、限流与批量写入。
- 主网公开接口同步 5,554 个市场。两家各启用 10 个永续市场，60 条默认周期流达到预热门槛，20 个市场取得有效 OI 和点差。两家均产生实时收盘事件，批量暂停和恢复通过。
- Bitget 的 REST 时间窗口在查询时排除收盘边界对应的下一根 K 线。BTCUSDT 的 `1Dutc` 样本通过 UTC 对齐验证。RAAPLUSDT 样本通过三根完整 REST `1m` 的合成检查，该样本的日线保持不可用。
- 通过 `npm.cmd run dev` 启动开发服务。Edge 验证了登录、目录筛选、启用现货、显示三个周期的收盘 OHLCV、添加额外周期、批量启停和删除配置。
